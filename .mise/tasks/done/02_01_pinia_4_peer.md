# 02_01 Require pinia 4 as the peer dependency

## Goal

Support only pinia 4: change `package.json` `peerDependencies.pinia` from `3.x` to `4.x`, refresh `yarn.lock` to match, and state the supported pinia version in the README requirements.

## Files to modify/create

- /Users/eric/Code/vue-bare-composables/package.json
- /Users/eric/Code/vue-bare-composables/yarn.lock (regenerated by `yarn install`, not hand-edited)
- /Users/eric/Code/vue-bare-composables/README.md

## Background

- The repo is `vue-bare-composables`, an npm library. Every push to `main` runs `.github/workflows/publish.yml`, which picks the version bump from Conventional Commit subjects and publishes to npm.
- Prior task 01_01 (done, commit `8dbc3a7 feat!: require Node.js 24`) raised `engines.node` to `>=24` and set README `## Requirements` to list `- Vue 3.x or higher` (README.md:31) and `- Node.js 24 or higher` (README.md:32). This branch already ships a major release.
- Commit `664b9c3 chore: update dependencies` moved the dev dependency to `"pinia": "^4.0.3"` (package.json:44) and added `@vue/devtools-api`. The peer range was left at `"pinia": "3.x"` (package.json:29), next to `"vue": "3.x"` (package.json:30).
- `yarn.lock` records the root workspace's peer ranges: the `vue-bare-composables@workspace:.` entry has `peerDependencies:` with `pinia: 3.x` (around yarn.lock:3245). It must match package.json or `yarn install --immutable` in CI fails.
- Pinia is used only by `src/useSnackbarStore.ts` (`defineStore`) and its test. README.md:11 already says "Pinia required for useSnackbarStore". No README or docs line names a pinia version today.
- Decision: the owner wants only pinia 4 supported. Dropping pinia 3 breaks pinia 3 users, so it ships in the same major release as the Node 24 change, under its own `feat!:` commit.

## Guides

- CLAUDE.md (doc, required): every commit subject and PR title, so releases bump the right version

## Implementation details

1. `package.json:29`: `"pinia": "3.x"` -> `"pinia": "4.x"`. Leave `"vue": "3.x"` and the dev dependency `"pinia": "^4.0.3"` unchanged.
2. Run `yarn install` at the repo root so the lockfile's workspace `peerDependencies` becomes `pinia: 4.x`. The only expected `yarn.lock` change is that line.
3. README `## Requirements`: add `- Pinia 4.x (only for useSnackbarStore)` between `- Vue 3.x or higher` and `- Node.js 24 or higher`.
4. Commit in one commit with subject `feat!: require pinia 4` and body footer `BREAKING CHANGE: pinia peer dependency is now 4.x; pinia 3 is no longer supported` (bare Conventional Commit subject, no prefix such as `Task 02_01:`), ending with the attribution line required by the session.

## Gotchas

- Do not run `yarn up` or change any other dependency version. If `yarn install` changes more than the workspace `peerDependencies` pinia line in `yarn.lock`, stop and report it.
- Keep the peer range form `4.x` (same style as `vue: 3.x`), not `^4.0.0` or `>=4`.
- The commit subject must start with `feat!:` exactly. `chore:` or `fix:` would publish an incompatible peer range without a major bump.
- Prettier checks README.md and package.json, so keep formatting as is.
